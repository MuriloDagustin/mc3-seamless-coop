  - type identity: [v+0x138], sent as an index into mgr+0x30

==================== update-freeze
RECIPE: PARTNER-SIDE PUPPET RECIPE (data only). Pointers: mgr = [[0x50152C]+0x08]; N = s16 [mgr+0x12C]; veh(i) = [mgr+0x130] + i*0x21C.

Approach: put every locally active ambient car into the game's own "scripted car whose route has ended" state (+0xC4=1, +0xAC=0). The game still runs 0x78940 for that car every frame. That path zeroes the speed and leaves the path inputs alone, then rebuilds the matrix from +0xC8 (anchor) and +0xD4 (heading) (0x767B0), calls phLevel UpdateObjectLocation ([0x5580F0] vt+0x20 on +0x2C), and re-bins the car in [0x5587D8] (0x2B74B0). ONCE, when the partner enters the race:

- byte [mgr+0x19C] = 0. This turns off the random lane-change planner 0x6C190.

HOST, every tick, for each i < N where u16 veh+0x2C != 0xFFFF (active), send:
- i and the type (ptr veh+0x138, or its index in the array at mgr+0x30);

PARTNER, every tick, for each local slot with +0x2C != 0xFFFF:

==================== spawn-centre
RECIPE: ANSWER: The traffic is not centred on one car. It uses one "traffic region" per human player. With setup+0x4C = 2 and setup+0x108 = 0, the host's traffic already spawns and keeps cars around player 1 (the partner car driven by data writes). The only condition is that player 1's car position, the matrix at phInst+0x10, is kept up to date on the host. Region 1 then follows it on its own every frame.

HOW IT WORKS (all static analysis):
- RS = [[0x5587E0]+0x5C]. This is the region set: 0x38 bytes, vtable 0x47609C, built in 0x2B8B20 -> 0x2BA740.
  - RS+0x18 = active region count. The player-manager ctor sets it to settings+0x4C (0x2BE210 -> 0x2B8CF0).
  - RS+0x14 = array of 8 regions, 0x0C bytes each. Region i = [RS+0x14] + i*0xC: +0 vtable 0x4760B4, +4 pointer to 3 circles, +8 lookahead.
  - Each circle is {cx, cz, r} (2D, x/z), at C+0x00, C+0x0C, C+0x18.
  - Default radii are 175/275/350 (ring0/ring1/ring2). Race modes reset all regions' radii via 0x2B8D50, e.g. 125/175/210.
- Every frame, each player's update 0x2C1520 calls 0x2B8D60(region = player+0x5C (= slot index), matrix, lookahead) at 0x2C17B9.
  - The matrix is [[player+0x14]+0x1C]+0x10, the phInst matrix; position at +0x24 (x) and +0x2C (z).
  - The lookahead is [[player+0x14]+8]+0xB0, the car speed.
  - 0x2BC410 puts ring0 on the car, and rings 1 and 2 1.5*lookahead ahead (local -Z).
- Every consumer loops over all RS+0x18 regions:
  - Road-segment candidate scan 0x2BA610/0x2BA2D0: a segment is a candidate if it is inside ring1 (plus its radius) of any region.
  - Spawn placement 0x6AA30: the point must be outside ring0 of every region and inside ring2 of a region.
  - Recycle 0x80C10: a car is kept if it is inside ring2 of any region (ring1 if veh+0x14E), otherwise 0x6A5C0 recycles it.
  - LOD 0x6A030 -> veh+0xB1: minimum distance to any region centre.
  - AI OutsideTraffic 0x1EA030: loops over player count.
- The pool is shared. The spawn budget is [mgr+0x68] (1 viewport; +0x70 when setup+0x08==2; +0x78/+0x7C in network). Reset 0x6C5D0 sets +0x68..+0x74 to the pool size +0x12C. So two distant players split the same pool, roughly half each.

HOST RECIPE (data only):
1. Set setup+0x4C = 2 before the race and player manager are built. Keep setup+0x108 = 0, setup+0x50 = 1, slot1+0x26 = 0.
2. Each tick, write the partner car's phInst matrix (+0x10..+0x3F, position at +0x34/+0x3C). Optionally write car+0xB0 (speed) so rings 1 and 2 lead the car.
3. Runtime check: [RS+0x18] == 2. Region 1's circle floats ([[RS+0x14]+0x0C+4] +0/+4, +0xC/+0x10, +0x18/+0x1C) must follow the partner.
4. Fallback if player 1 does not exist or its update does not run: write RS+0x18 = 2 (8 regions allocated, so up to 8 is possible). Then write region 1's 3 circle centres (keep the radii) from the mod thread every tick. Nothing else overwrites a region whose player is missing, and the spawn, recycle and LOD code all read RS+0x18. If the count is 2 but region 1 is never updated, the host spawns phantom traffic at world (0,0).
5. Do not set setup+0x50 = 2. With 2 viewports, 0x1DE4B0 -> 0x6A640 zeroes a finished player's radii, and the budget index changes.

C. PARTNER
- Write colour byte +0x16C on every slot the host reports. The draw code reads it each frame: 0x78ED5 movzx [drawable+0x148] = slot+0x16C, then indexes type+0x1FC+c*12. So the colour matches immediately.
- Write the matrix +0x34..+0x60 (and +0x74.. prev) and +0xE0 after the game's own update each frame. The renderer draws from the drawable at slot+0x24, whose matrix is at drawable+0x10 = slot+0x34 (GUESS by pattern).
- Stop local movement: byte [tm+0x144]!=0 makes BOTH the traffic update 0x6CC90 (test at 0x6CCAF) and the slice update 0x6CBC0 (0x6CBC3) return at once. No code ever writes it (only a copy at 0x6D20A), so it is a free freeze switch. The cost: no spawn/despawn and no renderer re-registration either. So on the partner you can only show slots that are already spawned locally. A slot the host spawns that is free on the partner has no render handle (u16 +0x2C==0xFFFF) and cannot be made visible by data alone. Practical hybrid: leave +0x144=0 so the partner's logic keeps spawning/registering, but overwrite matrix/colour/speed every tick (last writer wins). Partner slots the host says are inactive: move them to the host's position or under the map (GUESS). Validate with a test.
- Alternative lead (GUESS): the game's own network traffic is host-authoritative. In 0x6CBC0, if byte [tm+0x19C]!=0 and the session [0x557EFC] has +0x10>=0 and +0x10!=+0x18 (not host), it skips 0x6C190 (per-vehicle random turn/route choice at junctions, which uses the global rand at 0x6C2EF..0x6C30F). D. VALIDATION (both copies)
- Handshake: equal layout hash (A.5) and the same city index/name.
- Runtime: every N seconds the host sends CRC(colour bytes + active bits). The partner computes the same CRC after its writes. Optionally the partner reports the max |pos_partner(i) - pos_host(i)|.
- Re-handshake after any race start: Reset 0x6C5D0 (called from game-state entry 0x1EFE0 and 0x15A1E0) despawns every slot (0x7A190), sorts each type's free/used lists (0x7E140 qsort with comparator 0x7B890), and clears the scripted vector count. Layout is unchanged, but all slot states restart.

E. DO NOT RELY ON SEEDS
The traffic RNG is the shared MSVC-style global rand [0x4B2D00] (x*0x343FD+0x269EC3, >>16 &0x7FFF, inlined). It is also used by AI, race scripts, career, physics etc. It is reseeded at each race-state entry as seed = rand15(previous state), stored at [[0x4CBAE0]+0x14] (0x21170 -> 0x23DC0 -> 0x2D960; the replay restore is 0x2D900 / 0x212E0). Only 32768 seeds are possible. The second RNG [0x4B2D04] (used for +0x16E) is advanced by dozens of other systems and seeded from [0x534768] in 0x134BD0. Writing equal seeds will not keep the copies in lockstep, because consumption depends on each player's local state. So send colour and state per slot.
